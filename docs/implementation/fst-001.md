# IMP-FST-001 前后端联合模板实施

## 目标与范围

通过固定 Git submodule 引用独立前端与后端模板，提供一套安装、环境配置、数据库准备、开发、契约生成、验证和项目初始化流程。

## 技术约束与非目标

联合模板只承载编排，不复制前端/后端业务实现，不覆盖子仓库源文件。packages/web 指向 Preyou/ngt-starter，packages/server 指向 Preyou/yuumi-server，均固定提交。各自独立安装依赖，不启用根 Bun workspaces。提供开发 PostgreSQL 与 Redis compose，Logto 使用用户配置的服务。

## 代码结构与模块落位

package.json、.gitmodules、scripts/setup.ts、tasks.ts、create-project.ts；compose.yaml；README.md；.ai；docs。

## 接口实现契约

bun run setup 初始化固定子模块、按锁文件分别安装、从示例创建缺失的本地配置但不覆盖已有值；bun run dev 同时启动两端；bun run generate:web 从 Server 导出 OpenAPI 再调用前端生成器；bun run check 执行自身文档与两端检查；bun run build 构建前端。bun run create -- <新目录> 将已锁定模板展开为普通源码并创建新 Git 仓库，不携带子仓库 Git 信息、凭据、node_modules 或构建缓存；目标已存在时失败，不覆盖。

## 数据实现

| 数据     | 创建位置与唯一 owner                    | 读写入口                                 | 生命周期与失效                         |
| -------- | --------------------------------------- | ---------------------------------------- | -------------------------------------- |
| 固定版本 | .gitmodules 与 gitlink；所属 Git 仓库   | 子仓库先提交，父仓库显式更新引用         | 更新后重新安装和验证，不自动追踪 main  |
| 子进程   | scripts 中当前命令实例                  | 通过公开 Bun scripts 调用                | 退出或失败清理进程，非零退出不能伪成功 |
| 本地配置 | 用户的 .env.local 或首次从 example 复制 | setup 只创建缺失配置，用户显式编辑       | 不覆盖已有值，不提交或复制到新项目     |
| 展开项目 | create-project.ts 的目标目录            | 复制受版本控制内容，排除 Git、凭据、缓存 | 目标已存在即失败，失败不覆盖用户文件   |

不拥有前后端业务状态。安装或版本更新只使对应依赖与生成投影失效，随后调用其公开生成与验证命令。发布过程中不重写已发布标签。

## 组件实现

本仓库只编排两个子模板，不增加业务组件；前端通过其公开脚本生成与构建。

## 控制流程

tasks.ts 管理 dev/check/build/generate，setup.ts 初始化配置，create-project.ts 从根 HEAD 获取两个 gitlink，验证两端各自 Git 元数据和 HEAD 匹配固定提交。它用 git ls-tree 筛选各固定提交中的普通文件，再用 git archive 和 tar 展开提交内容。缺少或不匹配时返回非零并提示递归初始化；无 gitlink 的展开目录同样失败。根 .gitmodules 不进入展开项目。根脚本设定子进程的 cwd 后执行公开 Bun 命令，子进程失败返回非零；dev 任一进程退出时清理另一进程。compose 仅使用模板专用服务/命名卷和可配置宿主端口，不触碰 Storyworld 数据。create-project.ts 使用 mkdtemp 创建当前命令独占的暂存目录；完成复制与 Git 初始化后，以非递归 mkdir 独占目标，再 rename，避免检查后目标被并发创建时覆盖。失败只清理命令自己的暂存目录。创建项目导出根与两端固定提交，排除 .git 和私有环境文件，保留公开配置、环境示例与锁文件；新 Git 仓库不自动推送。

## 权限与安全

组织 upstream 的 push URL 为 DISABLED，只向 Preyou origin 发布。setup 不覆盖已有私有配置；create 只在新目标目录复制受版本控制内容，排除凭据和 Git 元数据。编排通过子仓库公开命令工作，不读取实际业务数据或实现资源授权。

## 状态一致性、事务与并发

子仓库提交后父仓库更新 gitlink；release-artifacts 产物标签先于应用版本消费。发布失败立即停止并保留已完成阶段，重试必须检查标签已存在且禁止覆盖。开发子进程并发启动，任一失败或收到信号时终止其余子进程。

## 代码边界

本仓库在 CLI 参数、目标目录与 Git 远端边界处理输入；业务校验由独立子模板负责。包内使用相对引用；跨仓库使用公开 exports、OpenAPI 或命令。配置及生成输入先修改再生成；构建目录只由工具产生。

## 技术异常处理

Git、固定引用校验、安装、构建与生成错误保持非零退出，输出失败阶段。

## 默认配置与隔离环境说明

setup.ts 继续只在缺少 packages/server/.env.local 时复制 Server 的 .env.example，不填入数据库名或凭据，也不覆盖已有配置。README 优先使用隔离的本地编排。已有外部服务时由开发者填写本地配置；手动 Compose 段说明 PostgreSQL 25432、Redis 26379 的独立开发端口以及由维护者填写连接串。dev:local 的 Compose 实例只使用项目自己的命名卷并在就绪后迁移。手动 Compose 的开发者显式执行迁移。选择 Compose 时由维护者设置唯一 COMPOSE_PROJECT_NAME，同机多项目分别设置 POSTGRES_PORT/REDIS_PORT；不改写 Compose 的现有参数接口。

## 外部依赖

根 Bun lock 从当前 package.json 使用 registry.npmjs.org 重新生成；不依赖地区镜像或预热缓存。

私有 Git 包安装使用调用方提供的 GITHUB_TOKEN 环境；setup 继承环境，不获取、输出或持久化 Token。

Bun、Git、系统 tar、发布时的已认证 GitHub CLI；联合模板开发数据库使用隔离 Docker Compose。其他仓库均通过公开安装、生成、检查命令调用。

## 性能与资源限制

不递归复制 node_modules、构建产物、Git 元数据或实际业务数据。一次安装只调用各目标仓库自己的安装入口，不叠加根 workspace 解析。

## 日志、监控与脱敏

命令记录执行阶段及失败退出，认证/请求日志脱敏；不输出 .env 内容、Token、Session 或组织凭据。验证记录区分受控联调、真实身份服务及浏览器结果。

## 迁移、兼容与回滚

组织仓库只读复制并记录来源提交；个人旧 Yuumi/Server 先保留备份标签。新项目直接使用统一 API，不建立旧包别名。回滚使用保留的个人 Git 提交；不改写源组织引用或已发布标签。

## 验证方案

bun run docs:check；bun run check；bun run build；全新目录 setup；固定子模块克隆；隔离 compose 数据库 migration；create 展开目录审计、提交后重新克隆、冻结安装与构建；未初始化、引用不匹配和预先存在目录均失败且不改数据。

## 联合开发实现

`dev-local.ts` 用忽略的 `dev.local` 保存项目标识和并发启动锁的端口，读取旧配置时继续复用已有标识和原端口。Compose 自动分配回环端口；迁移使用该项目的数据库。退出时先停止归属进程和 Compose 服务，再释放启动锁，保留数据卷。

`dev-local.ts` 在 Server 工作目录调用公开的 `auth:config`，取得模式、应用地址和 Logto 配置完整性。`local-config.ts` 校验本地绑定地址。启动器将地址和项目存储连接通过进程环境注入两端。Logto 上游参数由 Server 原样读取。开发建号命令查询正在运行的本项目 Compose 端口，再委托 Server 的 `auth:user`，直接转发标准输入。

正式运行由 `tasks.ts` 的 `start` 分支在两个子项目并发执行公开 `start` 命令，使用与 `dev` 一致的退出清理。`start:web` 委托 Web 的 `start`，使用其提交中的 `Caddyfile`。展开项目验证应确认该文件随 `packages/web` 保留，并在构建后通过前端入口实测 API。
