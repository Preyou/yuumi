# IMP-FST-001 前后端联合模板实施

## 目标与范围

通过固定 Git submodule 引用独立前端与后端模板，提供一套安装、环境配置、数据库准备、开发、契约生成、验证和项目初始化流程。

## 技术约束与非目标

联合模板只承载编排，不复制前端/后端业务实现，不覆盖子仓库源文件。packages/web 指向 Preyou/ngt-starter，packages/server 指向 Preyou/yuumi-server，均固定提交。各自独立安装依赖，不启用根 Bun workspaces。提供开发 PostgreSQL 与 Redis compose，Logto 使用用户配置的服务。

## 代码结构与模块落位

package.json、.gitmodules、scripts/setup.ts、tasks.ts、create-project.ts；compose.yaml；README.md；.ai；docs。

## 接口实现契约

bun run setup 初始化固定子模块、分别安装、从示例创建缺失的本地配置但不覆盖已有值；bun run dev 同时启动两端；bun run generate:web 从 Server 导出 OpenAPI 再调用前端生成器；bun run check 执行自身文档与两端检查；bun run build 构建前端。bun run create -- <新目录> 将已锁定模板展开为普通源码并创建新 Git 仓库，不携带子仓库 Git 信息、凭据、node_modules 或构建缓存；目标已存在时失败，不覆盖。

## 数据实现

| 数据     | 创建位置与唯一 owner                    | 读写入口                                 | 生命周期与失效                         |
| -------- | --------------------------------------- | ---------------------------------------- | -------------------------------------- |
| 固定版本 | .gitmodules 与 gitlink；所属 Git 仓库   | 子仓库先提交，父仓库显式更新引用         | 更新后重新安装和验证，不自动追踪 main  |
| 子进程   | scripts 中当前命令实例                  | 通过公开 Bun scripts 调用                | 退出或失败清理进程，非零退出不能伪成功 |
| 本地配置 | 用户的 .env.local 或首次从 example 复制 | setup 只创建缺失配置，用户显式编辑       | 不覆盖已有值，不提交或复制到新项目     |
| 展开项目 | create-project.ts 的目标目录            | 复制受版本控制内容，排除 Git、凭据、缓存 | 目标已存在即失败，失败不覆盖用户文件   |

不拥有前后端业务状态。安装或版本更新只使对应依赖与生成投影失效，随后调用其公开生成与验证命令。发布过程中不重写已发布标签。

## 组件实现

本仓库只编排两个子模板，不增加业务组件；前端通过其公开脚本生成与构建。

## 控制流程

保留旧 yuumi 历史并建立备份标签，再正常提交更新。tasks.ts 管理 dev/check/build/generate，setup.ts 初始化配置，create-project.ts 以 git ls-files -z 枚举根与两个子仓库跟踪文件；根 .gitmodules 和旧入口 index.ts 不进入展开项目。根脚本只通过 bun run --cwd <目录> <命令> 和公开命令编排，子进程失败返回非零；dev 任一进程退出时清理另一进程。compose 仅使用模板专用服务/命名卷和可配置宿主端口，不触碰 Storyworld 数据。create-project.ts 使用 mkdtemp 创建当前命令独占的暂存目录；完成复制与 Git 初始化后，以非递归 mkdir 独占目标，再 rename，避免检查后目标被并发创建时覆盖。失败只清理命令自己的暂存目录。创建项目复制 root 与两端受版本控制内容，排除 .git/.env\*.local，.env 示例保留；新 Git 仓库不自动推送。

## 权限与安全

组织 upstream 的 push URL 为 DISABLED，只向 Preyou origin 发布。setup 不覆盖已有私有配置；create 只在新目标目录复制受版本控制内容，排除凭据和 Git 元数据。编排通过子仓库公开命令工作，不读取实际业务数据或实现资源授权。

## 状态一致性、事务与并发

子仓库提交后父仓库更新 gitlink；release-artifacts 产物标签先于应用版本消费。发布失败立即停止并保留已完成阶段，重试必须检查标签已存在且禁止覆盖。开发子进程并发启动，任一失败或收到信号时终止其余子进程。

## 代码边界

本仓库在 CLI 参数、目标目录与 Git 远端边界处理输入；业务校验由独立子模板负责。包内使用相对引用；跨仓库使用公开 exports、OpenAPI 或命令。配置及生成输入先修改再生成；构建目录只由工具产生。

## 技术异常处理

Git、安装、构建、生成和 gh API 错误保持非零退出，输出失败阶段且停止后续发布。缺少 GitHub 登录只阻塞远端创建和发布，不伪造迁移完成。

## 默认配置与隔离环境说明

setup.ts 继续只在缺少 packages/server/.env.local 时复制 Server 的 .env.example，不填入数据库名或凭据，也不覆盖已有配置。README 的首选步骤使用当前服务器并要求先编辑本地配置；可选 Compose 段说明 PostgreSQL 25432、Redis 26379 的独立开发端口以及由维护者填写连接串。compose.yaml 与编排代码保持现有接口，根不创建当前服务器数据库或自动执行迁移。选择 Compose 时由维护者设置唯一 COMPOSE_PROJECT_NAME，同机多项目分别设置 POSTGRES_PORT/REDIS_PORT；不改写 Compose 的现有参数接口。

## 外部依赖

根 Bun lock 从当前 package.json 使用 registry.npmjs.org 重新生成；不依赖地区镜像或预热缓存。

私有 Git 包安装使用调用方提供的 GITHUB_TOKEN 环境；setup 继承环境，不获取、输出或持久化 Token。

Bun、Git、发布时的已认证 GitHub CLI；联合模板开发数据库使用隔离 Docker Compose。其他仓库均通过公开安装、生成、检查命令调用。

## 性能与资源限制

不递归复制 node_modules、构建产物、Git 元数据或实际业务数据。一次安装只调用各目标仓库自己的安装入口，不叠加根 workspace 解析。

## 日志、监控与脱敏

命令记录执行阶段及失败退出，认证/请求日志脱敏；不输出 .env 内容、Token、Session 或组织凭据。验证记录区分受控联调、真实身份服务及浏览器结果。

## 迁移、兼容与回滚

组织仓库只读复制并记录来源提交；个人旧 Yuumi/Server 先保留备份标签。新项目直接使用统一 API，不建立旧包别名。回滚使用保留的个人 Git 提交；不改写源组织引用或已发布标签。

## 验证方案

bun run docs:check；bun run check；bun run build；全新目录 setup；固定子模块克隆；隔离 compose 数据库 migration；create 展开目录审计、安装与构建；预先存在目录拒绝且不改数据。

## 实施顺序

1. 先写并确认总体与详细设计，再形成本文。
2. 按本文代码落位实施本仓库。
3. 更新生成输入并运行生成器。
4. 按验证方案完成本仓库检查。
5. 记录结果、提交本仓库，再更新消费仓库固定引用。

## 完成条件

公开契约、源码、文档、生成物和发布产物一致；所有规定检查通过；真实外部环境未验收的部分明确记录，不以构建成功替代运行验收。
