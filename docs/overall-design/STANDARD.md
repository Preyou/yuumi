# 总体设计规范

## 目标读者与职责

总体设计面向产品负责人和项目参与者，描述项目目标、产品边界、模块划分和计划提供的能力，回答“做什么”，不回答“如何实现”。

## 元数据

总体设计必须使用以下 Front Matter：

```yaml
---
schema_version: 1
document_type: overall-design
id: OD-001
title: 示例标题
status: 构想 | 已规划 | 已废弃
relations:
  detailed_design:
    - id: EXAMPLE-001
      path: ../detailed-design/example-001.md
---
```

总体设计标识格式为 `OD-NNN`，其中 `NNN` 是三位数字，例如 `OD-001`。

- `构想` 可以不关联详细设计，此时使用 `relations: {}`。
- `已规划` 必须至少关联一个详细设计。
- `已废弃` 可以保留历史关系，但正文必须说明废弃原因或替代方向。

## 必需内容

- 目标或产品愿景。
- 产品边界。
- 模块或能力划分。
- 每项能力的状态和对应详细设计。
- 当前范围之外的能力。

不适用的章节必须保留并说明原因，不得直接删除。

总体设计中的“当前范围之外”只表示没有纳入当前产品承诺，不代表必须主动阻止相关用途。需要禁止的业务行为必须在详细设计中规定原因和用户可见结果，不能由“范围之外”直接推导。

## 禁止内容

总体设计不得规定：

- API、路由或协议契约；
- 数据表、字段、索引或迁移；
- 代码模块、组件或文件路径；
- 技术框架、依赖库或部署实现；
- 代码层面的异常、事务或并发策略。

## 专业图表

总体设计应优先使用专业图表表达产品方向、范围、能力及其关系。只有模块和能力关系比较简单，并且文字描述比图表更简洁、清晰时，才可以省略图表。可以使用的图表包括：

| 图表类型       | 适用场景                                 | Markdown 表达方式        |
| -------------- | ---------------------------------------- | ------------------------ |
| 产品上下文图   | 表达产品与用户、外部组织或外部系统的关系 | Mermaid `flowchart`      |
| 产品边界图     | 区分产品负责和不负责的范围               | Mermaid `flowchart` 子图 |
| 能力地图       | 展示产品模块及计划提供的能力             | Mermaid `mindmap`        |
| 业务领域图     | 表达业务领域及其关系，不展开技术模块     | Mermaid `flowchart`      |
| 利益相关者图   | 展示用户、业务角色及其利益关系           | Mermaid `flowchart`      |
| 业务价值链图   | 表达从业务输入到最终价值的主要环节       | Mermaid `flowchart`      |
| 路线图或阶段图 | 展示构想、规划和交付阶段                 | Mermaid `timeline`       |

总体设计图表只能表达产品方向、范围和能力，不得使用数据库 ER 图、接口时序图、代码类图、技术组件图或部署图替代下游设计。

## 完整性与评审

进入 `已规划` 前必须确认：

- 目标和边界可以独立理解；
- 模块范围互斥且没有明显遗漏；
- 每项已规划能力都有有效详细设计关系；
- 没有使用技术实现替代产品决策；
- 范围外能力被明确记录。
